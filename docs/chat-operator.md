# ChatGPT operator contract

War Reporter exposes one narrow machine command endpoint for ChatGPT through GitHub Issue comments.

## Control endpoint

- Repository: `vokerg/war_reporter`
- Control issue: `#155` — https://github.com/vokerg/war_reporter/issues/155
- The issue is permanent. Do not create a new issue per collection.
- The GitHub connector identity has been verified to publish comments as `vokerg` with `author_association=OWNER`.

## Commands

User-facing ChatGPT request:

`собери вчера`

maps exactly to the GitHub control comment:

`/collect yesterday`

ChatGPT must add that exact comment to control issue `#155`. The bridge accepts no arbitrary date, workflow, ref or CLI argument.

## Collection flow

Before posting the command, ChatGPT should record the latest visible `Collect OSINT` workflow run ID or creation time. This gives a baseline so a nearby cron-triggered run is not mistaken for the command-triggered run.

After posting the control comment, ChatGPT must:

1. Find the new `Collect OSINT` workflow run from `.github/workflows/collect.yml` on `main` that is newer than the recorded baseline. The dispatched run uses event `workflow_dispatch`; do not treat an older or cron-only run as evidence that the command was accepted.
2. Follow the existing collector run; do not invoke a second collector or create a parallel write path.
3. Check both jobs:
   - `collect` produced and uploaded the validated collection artifact;
   - `persist` verified the artifact and completed its write to `main`.
4. Treat collector status `partial` as degraded coverage, not as absence of a result. If `collect` is red because the one-shot collector returned non-zero, still check whether the validated artifact was created and whether `persist` completed successfully.
5. After `persist`, fetch the new `main` head and read `data/state.json` plus the generated daily report.
6. Return to the user:
   - collection `status`;
   - `sources_attempted`;
   - `sources_succeeded`;
   - `errors`;
   - `sources_skipped`;
   - material count from the report header (`Сохранено материалов`);
   - report source count from the report header (`Уникальных источников`);
   - persisted `main` commit SHA;
   - direct report link: `https://github.com/vokerg/war_reporter/blob/main/reports/daily/YYYY-MM-DD.md`.

If no newer `Collect OSINT` `workflow_dispatch` run appears, inspect the corresponding `Chat control` run before retrying. Do not post repeated commands blindly, because each accepted comment intentionally queues another production collection.

A concise successful operator response should look like:

`Готово: 1110 материалов, 59 источников, status partial, 40 source errors. Report: <direct link>. Commit: <sha>.`

The date in the report link is the report date generated by the production pipeline for the requested "yesterday" snapshot; do not synthesize historical collection semantics with a large lookback.

## Status-only request

`статус сбора` does not require a new run. ChatGPT should inspect the latest `Collect OSINT` workflow run and current `data/state.json`, and report the latest persisted state.

## Security boundary

Issue comments are untrusted input. Only control issue `#155`, repository `vokerg/war_reporter`, owner login `vokerg`, `author_association=OWNER`, and the exact `/collect yesterday` command are accepted. Comment text must never become shell code, CLI arguments, workflow names or refs.

The untrusted command parser runs in a job with no repository token permissions. Only a second job, reached through the parser's boolean allowlist output, receives `actions: write`, and it dispatches the fixed `collect.yml` workflow at fixed ref `main`.

## E2E constraint

GitHub evaluates `issue_comment` workflows from the repository default branch. Therefore a new `chat-control.yml` that exists only on a feature branch cannot receive a real `issue_comment` event before merge. Pre-merge evidence is limited to CI/regression tests plus verification of the connector comment identity. The full ChatGPT → issue comment → Actions dispatch → artifact → persist → report path must be exercised after the bridge is merged to `main`.
